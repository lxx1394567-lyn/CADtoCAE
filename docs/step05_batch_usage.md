# Step05 v1.3: single folder, built-in SP_SC / SP_DC rules

Select Project Folder, Scan Projects, then Generate All Ready or Generate
Selected. Include Subfolders defaults OFF. There is no Source/Output split or
same-folder collision restriction. Duplicate IDs are reported without merging
inputs across directories. SP_SC and SP_DC FULL capability with READY inputs enables
generation; successful previous generation does not disable another run.

The executable contains DEFAULT_SP_SC_ANALYSIS_CONFIG. It uses the same input
schema validation and engineering resolvers as the validated legacy workbook.
Defaults: beam half-patch 50 mm, brace end 50 mm, SIDE2/SIDE2, all four rules
enabled, DISTRIBUTING with all six DOFs ON. The reserved column-top length is
50 mm; natural top ring edges remain the actual target. SP_SC engineering rules remain unchanged.

For each project, only <project_id>_analysis_plan.json and
<project_id>_analysis_setup.py are generated directly in Project Folder. The
Plan records the internal config identifier and complete values for traceability.
No analysis.xlsx is required, read, copied, or generated by this GUI workflow.
Old workbooks are left unchanged. Explicit workbook configuration remains
available to developer APIs/tests only. Input workbooks and summaries stay intact.

Input and Generation states are separate. During generation a project shows
GENERATING, then GENERATED or FAILED with a short Result. The log contains
per-project progress, full failure diagnostics and totals. Completion shows an
information dialog or a warning dialog with succeeded/failed counts and output
folder. Full rule names appear in selection details in the log; the main table
uses compact FULL capability and Result columns.

Scan detects generated artifacts by plan/script only: both -> GENERATED,
neither -> NOT_GENERATED, one -> PARTIAL. Workbook presence has no effect.
Generated-file existence does not mean the script has been validated in Abaqus.

Generation stages data temporarily, publishes only the two generated files and
rolls back partial publication on errors. Per-project failures do not stop the
batch. JSON/TXT batch summaries live in Project Folder. Runtime reports also
point there. The GUI never runs Abaqus or generates final mesh.

Build scripts/build_step05_exe.ps1 uses .venv_step05_build. The canonical package
is dist/CADtoCAE_Step05_AnalysisSetup; retain _internal beside the EXE. The title
and startup log identify v1.3 / Built-in Rules and show the executable path.
Older packages under alternate dist subfolders are historical development builds.

SP_DC adds DEFAULT_SP_DC_ANALYSIS_CONFIG: common BEAM_BRACE_TIE,
COLUMN_BEAM_TIE (column top 50 mm; beam projected station +/-50 mm), and
COLUMN_HOOP_TIE for every complete A/B group. It creates 4+2N Ties and no
COLUMN_COLUMN_TIE, RP or Coupling. SP_DC ANG17 and ANG28 have passed user-performed Abaqus/CAE 2020 validation.
ANG21 still requires review of HOOP_03 / COLUMN_DOWN geometry. DP remains
unsupported at this checkpoint and is the next Step05 development scope.

Column/beam contact faces are selected at runtime from C_CHANNEL shell patches
by compatible normals, minimum normal distance, then center distance; ambiguous
pairs fail. Shell sides follow contact direction. For coincident midsurfaces,
opposing C-section limbs must establish a unique direction; otherwise fail.
Candidate IDs, selected IDs and physical sides are written to the CAE report.
All affected geometry is partitioned before the final connection regions are
selected, and geometry-level duplicate-slave checks precede Tie creation.
HOOP group IDs namespace local half splits, surfaces and Ties. Groups are sorted
by axial position; overlapping bands require review. SP_SC single-group names
remain unchanged. No native mesh is required and materials are not removed.

HOOP compatibility (v1.3): HOOP, HOOP_<n> and HOOP_ASSEMBLY_<n> share the
Step05 canonical matcher. A unique exact Part name must identify a HOOP_BAND
component. Raw summary and component-record codes remain unchanged and are
recorded alongside canonical_role in the plan and runtime report.

Selecting a project displays Status, Supported Rules, Missing Requirements,
Warnings, First Blocking Reason and expected Tie counts in the lower log/details
area. A partial HOOP band beyond COLUMN_DOWN is NEEDS_REVIEW, even with a complete
A/B pair. Its actual ranges and overlap are displayed. Generate All Ready skips
such projects with an explicit log entry and continues with the ready projects.
It never moves/trims a hoop or extends a column to bypass this review.
